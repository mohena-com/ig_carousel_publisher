# Instagram Carousel Publisher

Publishes exactly six carousel slides generated by `ig_carousel_app` as **one Instagram carousel post**.

## Architecture

```text
ig_carousel_app
      |
      v
output_carousel/<JOB_NAME>/
  slide_1.png ... slide_6.png
      |
      v
instagram_carousel_publisher
      |
      +--> convert PNG -> JPEG
      +--> upload images to public hosting
      +--> create 6 Instagram child media containers
      +--> create 1 CAROUSEL parent container
      +--> wait for readiness
      +--> publish ONE Instagram post
```

This workspace deliberately keeps publishing separate from carousel generation.

## Current Meta API design

This implementation uses the **Instagram API with Facebook Login** because the Instagram Creator account is already connected to the Facebook Page `Shaktidootam`.

Meta's current documentation says this route supports Instagram Professional accounts (Business and Creator) and requires a Page linked to the professional Instagram account. The publishing flow uses a Page access token and the Instagram professional account ID.

For image publishing, Meta fetches the image from a publicly accessible URL, so local PNG paths cannot be sent directly to Instagram. This workspace therefore includes a Cloudinary uploader.

## Safety

- Default command is `--dry-run`; it never publishes.
- `--publish` is required for the final write operation.
- Exactly six images are required.
- Images are converted to JPEG before upload.
- A local publication ledger prevents accidental duplicate publication of the same job directory.
- Never put passwords, 2FA codes, cookies, or tokens in chat.
- `.env` is ignored by git.

## Discover the connected Page

```bash
./run.sh doctor
```

This calls Meta's `/me/accounts` endpoint and selects the Page by `META_PAGE_NAME`, then obtains its linked Instagram professional-account ID. Secret tokens are not written to `data/account.json`.

## Dry run

```bash
./run.sh publish \
  --input-dir "../output_carousel/JOB_NAME" \
  --caption "Latest government job notification. Check the slides for eligibility, dates, fees and application details." \
  --dry-run
```

Dry run validates six slides, image readability, JPEG conversion, credentials, account discovery, and duplicate state. It does not create Instagram containers or publish.




## Real publication

```bash
./run.sh publish \
  --input-dir "../output_carousel/25_NTPC_Sail_Power_Company_Limited_NSPCL_Recruitment_2026_Apply_Online_For_16_Post_2026-09-07" \
  --caption "Latest government job notification. Check the slides for eligibility, dates, fees and application details." \
  --publish
```

The app creates six child media containers, creates one `CAROUSEL` container referencing them, waits until the carousel is ready, and calls `media_publish` once.

## Duplicate protection

Successful publications are recorded in `data/publications.json`. The fingerprint is based on all six image bytes plus the caption, so an unchanged set cannot accidentally be published twice.
